## TASK

`_apply_migrations()` in `src/prusa_mcp/db.py` wraps every migration statement in
`except Exception: pass`, then records the version in `schema_version` regardless.
Make it tolerate only the one expected failure and surface everything else.

## CONTEXT

- The swallow exists because SQLite has no `ALTER TABLE ... ADD COLUMN IF NOT EXISTS`:
  on a fresh DB the columns can already exist, and the ALTER raises
  `sqlite3.OperationalError: duplicate column name: ...`. That case must stay tolerated.
- Any other error (syntax error, missing table, locked DB) is currently hidden, and the
  version is still marked applied, so the migration never retries.
- There are no migration tests today.

## FILES

- `src/prusa_mcp/db.py` (edit: `_apply_migrations` only)
- `tests/test_migrations.py` (new)

Out of scope: every other file, `MIGRATIONS` contents, `init_db`, and the schema.

## CONSTRAINTS

- Catch `sqlite3.OperationalError` (aiosqlite re-raises sqlite3 exceptions) and tolerate it only
  when the message contains `duplicate column name`. Re-raise everything else.
- If a statement fails with a non-tolerated error, do **not** insert that version into
  `schema_version`.
- No new dependencies. Use in-memory SQLite (`:memory:`) in tests; never touch `data/prints.db`.
- Ruff-clean (`ruff check`).
