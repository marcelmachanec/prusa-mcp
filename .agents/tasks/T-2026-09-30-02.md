## TASK

Reject negative filament usage. Today `use_filament(db, id, -50)` and
`log_print(..., filament_used_g=-50)` both *add* 50 g to the spool, because
`_deduct_filament_no_commit` computes `remaining_g - grams_used`. Negative grams must raise
`ValueError` and change nothing. (Decided by Marcel: reject, don't clamp.)

## CONTEXT

- The `use_filament` MCP tool's docstring says "grams consumed by the print", so negative input is never valid.
- Existing pattern to follow: `db.py` raises `ValueError` for invalid input (see the invalid print-status
  check in `log_print`, and `update_filament`'s status check). The MCP layer surfaces it as a tool error,
  so `server.py` needs no change.
- 0 g stays valid (no-op), as today.

## FILES

- `src/prusa_mcp/db.py` (edit: `use_filament`, `log_print`, and `_deduct_filament_no_commit` if useful)
- `tests/test_filament.py` (add tests)

Out of scope: `server.py`, every other file, and the read-modify-write/concurrency behaviour of the deduction.

## CONSTRAINTS

- **Validate before any write.** In `log_print` the check must run before the `INSERT INTO print_log`,
  so that a rejected call leaves no pending uncommitted row on the connection (a later commit by
  another call would otherwise persist it).
- Error message: `grams_used must be >= 0` (or `filament_used_g must be >= 0` in `log_print`), matching
  the style of the existing `ValueError` messages.
- No new dependencies. Ruff-clean on changed lines.
