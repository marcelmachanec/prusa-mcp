## TASK

Add a print watcher: a long-running command `prusa-watch` that polls PrusaLink every 30 s, notices when
a print job ends, and records it with the existing `db.log_print` (which also deducts filament when a
spool and grams are given). Goal: Marcel never has to log a print by hand.

## CONTEXT

- The MCP server only runs while Claude Code is open, so the watcher is a **separate process**
  (started by Windows Task Scheduler at logon — set up later, not in this task).
- Printer is a Prusa MK4. Verified 2026-11-21 with the current API key (`X-Api-Key` header):
  - `GET /api/v1/status` → 200, `{"printer": {"state": "IDLE", ...}, "storage": {...}}`. No material field.
  - `GET /api/v1/job` → **204, empty body when no job is running**.
  - `GET /api/printer` (legacy) → `telemetry.material` holds the loaded material, e.g. `"PETG"`.
- `PrusaLinkClient` (`prusalink.py`) takes an optional `transport=` for `httpx.MockTransport` tests
  (see `tests/test_prusalink.py` for the pattern).
- Schema changes go through `db.MIGRATIONS` (next version: 4 — T-04 owns 3). Never edit existing migrations.
- `db.list_filaments(db, status=..., material=...)`; spool statuses: sealed, active, low, empty, archived.

## DESIGN (decided by Claude, Marcel said "dive in")

1. **Pure tracker, thin loop.** `watch.py` holds a `JobTracker` with
   `observe(job: dict | None, now: datetime) -> FinishedJob | None`. It is fed the parsed
   `/api/v1/job` body (`None` for 204) and returns a finished job when one ends. The async loop
   (`run(client, db, interval_s=30)`) only polls, calls `observe`, and records. All logic is testable
   without a network.
2. **When a job counts as ended:** the job's state becomes FINISHED / STOPPED / ERROR (record once), or
   the job disappears (204) or its id changes while a job was being tracked.
3. **Status mapping:** FINISHED → `completed`, STOPPED → `cancelled`, ERROR → `failed`. If the end state
   was never seen (job just vanished, e.g. PC slept): last progress ≥ 99 → `completed`, else
   `cancelled`; add note `"watcher: end state not observed"`.
4. **Times:** `finished_at` = `now` at detection; `duration_s` = last seen `time_printing`;
   `started_at` = `finished_at - duration_s` (ISO strings, like the rest of `print_log`).
5. **Spool:** read the material from legacy `/api/printer` → `telemetry.material`. If exactly one spool
   with status `active` or `low` has that material (case-insensitive), pass its `filament_id`.
   Otherwise pass no spool and note `"watcher: spool? (<n> candidates for <material>)"`. A wrong guess
   is worse than none.
6. **No double logging:** migration 4 adds `print_log.printer_job_id INTEGER`. Before recording, skip if
   a row with the same `printer_job_id` and `filename` exists. Restarting the watcher mid-print is fine.
7. **Errors:** a failed poll (network/HTTP error) is logged to stderr and the loop continues; it never
   ends a tracked job by itself.
