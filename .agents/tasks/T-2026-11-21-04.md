## TASK

"Spool truth": three MCP tools so the spool numbers match reality and are useful.

1. `weigh_spool(filament_id, gross_g, tare_g=None)` — Marcel weighs a spool on a kitchen scale; the
   tool sets `remaining_g = gross_g - tare`, where tare is the empty spool's weight.
2. `shopping_list()` — what to buy: spools that are `low` or `empty`, plus stock and usage per material.
3. `monthly_report(month=None)` — prints, hours, grams, cost and failure rate for one month.

## CONTEXT

- Real data today: 14 spools, all `sealed`, all `weight_g = remaining_g = 1000`. Brands: Colorfil,
  Nebula, Devil Design, Matny (cardboard/plastic spools), Rosa3D "Refill spool" (no spool, tare 0 —
  the word "Refill" is in their `notes`).
- Spool statuses: sealed, active, low, empty, archived. `_deduct_filament_no_commit` in `db.py` holds the
  current status rule: 0 g → `empty`; < 15 % of `weight_g` → `low`; `sealed` → `active` (and stamps
  `opened`). Reuse the same thresholds — factor them into one helper rather than copying them.
- `settings` table stores floats (`get_setting` / `set_setting`); defaults live in `DEFAULTS_SETTINGS`.
- Schema changes go through `db.MIGRATIONS`. **This task owns migration 3.** (T-03 watcher moves to 4.)
- `print_log` has `started_at`, `duration_s`, `filament_used_g`, `filament_id`, `status`,
  `cost_breakdown_json`, `quoted_price`, `is_quote` (1 = a quote, not a real print — exclude from reports).

## DESIGN (decided by Claude; Marcel said "guess" for tare)

- Migration 3: `ALTER TABLE filament ADD COLUMN tare_g REAL` (nullable). Add it to the `Filament`
  dataclass and `to_dict`.
- New default setting `default_spool_tare_g = 200` (unit `g`).
- Tare used by `weigh_spool`, first match wins: the `tare_g` argument (and store it on the spool) →
  the spool's stored `tare_g` → `default_spool_tare_g`.
- `remaining_g = clamp(gross_g - tare, 0, weight_g)`. Status from the shared helper. A `sealed` spool
  that is weighed becomes `active` with `opened` = today, unless it weighs ≥ `weight_g + tare`
  (still full → stays `sealed`).
- `gross_g < 0` or `tare_g < 0` → `ValueError`. Unknown spool → error JSON like other tools.
- `shopping_list` returns `{"to_buy": [...low/empty spools...], "stock_by_material": {material:
  {"spools": n, "remaining_g": sum}}, "used_last_90d_g": {material: grams}}`. Archived spools excluded.
- `monthly_report(month="YYYY-MM")` (default: current month) returns totals: prints, completed, failed,
  cancelled, failure_rate_pct, print_hours, filament_g, cost (sum of `cost_breakdown_json` totals where
  present, `null` if none), and a per-material breakdown (via `filament_id` → `filament.material`).
  `is_quote = 1` rows excluded.
- DB logic in `db.py`; the three tools in `server.py` stay thin (pattern: existing tools).
